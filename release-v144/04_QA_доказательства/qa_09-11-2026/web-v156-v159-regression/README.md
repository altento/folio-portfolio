# Web/PWA v156 через локальный host Windows v159 — regression QA

Проверка выполнена 09.11.2026 на точной сборке `dist/folio-webview-v159/folio-desktop/folio-desktop.exe`, которая обслуживала ресурсы v156 на loopback `127.0.0.1:41766`. Адаптивность и пользовательские сценарии запускались в установленном Chrome через отдельный изолированный Playwright-контекст; личный Chrome-профиль и основная база приложения не использовались.

## Результаты

- 20/20 комбинаций: четыре маршрута (`dashboard`, `projects`, `showcase`, `settings`) × пять размеров (320×568, 390×568, 390×844, 768×900, 1440×900).
- Горизонтальное переполнение: 0; битые изображения карточек: 0; ошибки страницы и консоли: 0.
- Элементы управления ниже 44 CSS px: 0. Для чекбоксов измерялась вся связанная область `<label>`.
- Offline cold reload: Service Worker был контроллером, приложение оставалось офлайн, три демо-кейса и изображения карточек загрузились.
- Мобильный мастер формы отображался. Синтетический кейс создан, сохранён после перезагрузки, отредактирован, восстановлен через Undo и окончательно удалён после истечения 7,4-секундного Undo-окна; осталось ровно три демо-кейса.

Полные измерения и SHA-256 десяти кадров находятся в `result.json`. Восемь кадров покрывают мобильные/desktop dashboard и каталог, настройки и offline dashboard.

## Границы

Маршрутная матрица, CRUD и offline проверены в Chrome-контексте, использующем локальный host и ресурсы v156 из сборки Windows v159. Нативное окно v159 отдельно открыто и проверено на dashboard и витрине. Это не ручной проход всех экранов мышью/клавиатурой и не подтверждение Narrator, TalkBack или физического телефона.
