# Короткий сценарий демонстрации модулей ООП 4–5

Ориентир на 6–8 минут. Сценарий подготовлен для показа требований курса на Tkinter-приложении из `02_Приложение/main.py`. Современный WebView2/PWA — более позднее развитие проекта; при защите не следует приписывать его исходным этапам модулей 4–5.

## Подготовка без риска для личных данных

1. Распакуйте комплект в отдельную папку и откройте PowerShell в `02_Приложение`.
2. Для запуска исходного Tkinter-кода выполните `python -m pip install -r requirements.txt`, затем `python main.py`. Нужен Python 3 с Tkinter; приложение создаст SQLite-файл рядом с `main.py`.
3. На первом запуске без базы появятся демонстрационные записи. Для показа создания, редактирования и удаления используйте только отдельную распакованную копию комплекта.

`Запустить приложение.bat` запускает современную WebView2-версию. Для демонстрации именно требований Tkinter-модулей используйте `python main.py`.

## Порядок показа

### 1. Предметные классы и полиморфизм — около минуты

Покажите проекты разных типов и окно подробностей. Кратко поясните, что общий абстрактный `Project` задаёт контракт, а `LandingProject` и `WebAppProject` предоставляют собственную реализацию `get_main_link()`. `Portfolio` хранит и обрабатывает коллекцию; модель разработчика отделена в `Developer`. Если попросят показать код, откройте `portfolio_core.py` и раздел UML в отчёте модуля 4.

### 2. Добавление, редактирование и подтверждение удаления — около полутора минут

1. Нажмите «Добавить», выберите тип, заполните название и описание; сохраните карточку.
2. Выберите её и откройте редактирование; измените описание и сохраните.
3. При удалении сначала отмените подтверждение, затем удалите карточку в этой временной копии. Это показывает обе ветки диалога и не затрагивает рабочие данные.

Поясните, что форма строится по типу проекта, а непустые обязательные поля проверяются до сохранения.

### 3. Поиск, фильтр и сортировка — около минуты

1. Введите `карта`: останется проект с таким названием.
2. Очистите строку: вернутся все записи. При необходимости покажите поиск по числовому ID.
3. Выберите фильтр по типу или статусу, затем верните «Все»; покажите сортировку.

### 4. SQLite и перенос данных — около двух минут

1. В меню «Файл» покажите «Сохранить», «Сохранить базу как…» и экспорт JSON/CSV.
2. Экспортируйте JSON; откройте его через «Открыть базу данных / JSON…» и покажите предпросмотр/объединение, если он предложен для выбранного файла.
3. Закройте и снова запустите программу из той же временной копии: сохранённые карточки должны остаться.
4. Если нужно связать desktop с веб/PWA, используйте JSON как явный переносимый формат. Отдельные локальные хранилища автоматически не синхронизируются.

Форматы SQLite/JSON/CSV и проверенные сценарии описаны в отчёте и матрице требований модуля 5. Не открывайте для демонстрации личную базу из `%LOCALAPPDATA%\\Folio`.

### 5. О программе и завершение — около минуты

Покажите отдельное окно «О программе» с `Label`, рисунком `Canvas` и кнопкой возврата. Завершите коротким резюме: модуль 4 — классы, наследование, полиморфизм и GUI; модуль 5 — хранение, поиск, фильтрация, валидация и обмен файлами. Текущий Web/PWA v132 и Android — расширение после учебного среза, отражённое отдельно в QA-документации.

## Если что-то пошло не так

- Нет Python-зависимости для изображений: в папке приложения выполните `python -m pip install -r requirements.txt`.
- Записи неожиданно не демонстрационные: закройте окно и распакуйте архив в новую временную папку. Не удаляйте и не заменяйте личные файлы.
- Преподаватель просит показать только логику: используйте изолированную копию и тесты из `02_Приложение/tests`; не используйте текущую рабочую базу.

Официальный код учебной группы по найденным исходникам окончательно не установлен: модуль 1 и модули 2–5 расходятся. Перед защитой не исправляйте титульные данные по догадке; сверьте их с утверждённой ведомостью или шаблоном.
