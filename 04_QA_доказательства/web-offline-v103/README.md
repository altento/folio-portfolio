# Проверка офлайн-навигации PWA v103

Дата: 02.11.2026. Все сценарии проверялись в изолированном браузерном контексте Playwright на копии текущей веб-сборки, опубликованной по адресу `http://127.0.0.1:8769/folio/`. Такой путь специально имитировал размещение приложения не в корне домена, а в подпапке. Сеть отключалась средствами браузера после предварительного заполнения кэша service worker.

## Результат

- Service worker активировался со scope `/folio/` и кэшем `folio-shell-v103-offline-navigation`.
- Холодный офлайн-переход на `/folio/?build=offline-query-check` открыл приложение, сохранил query-параметр и показал рабочую оболочку.
- Переход на не сохранённый вложенный путь офлайн открыл понятную страницу «Нет соединения», вместо частично сломанной оболочки без CSS и скриптов.
- Кнопка страницы без сети разрешилась в `http://127.0.0.1:8769/folio/` и вернула в приложение без подключения.
- На ширине 390 CSS px для страницы офлайн-ошибки `document.scrollWidth = 390`: горизонтального переполнения не было.
- Модульные тесты Service Worker и PWA прошли вместе с веб-регрессией: 40/40.

## Кадры

- `desktop-cold-offline-query.jpg` — холодный офлайн-запуск с query-параметром.

- `mobile-offline-fallback-subpath.jpg` — страница «Нет соединения» и возврат из подпапки.

## Ограничения проверки

Использована локальная эмуляция сети и CSS-ширины в Chromium, не физический телефон. Не проверялись Safari/iOS, экранный диктор, системный масштаб Windows/Android и установленная PWA на реальном устройстве. Эта проверка не подтверждает облачную синхронизацию; приложение остаётся local-first.
