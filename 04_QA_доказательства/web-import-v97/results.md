# Web/PWA v97 — ручная проверка JSON-импорта изображений

Дата: 02.11.2026. Выполнено в новой временной вкладке локального приложения `http://127.0.0.1:8767/` с демонстрационным набором из трёх проектов. Настоящий пользовательский браузер Chrome и основная SQLite-база настольного приложения не использовались.

Каждый тест проходил через кнопку «Импортировать JSON» и реальное событие выбора файла (`filechooser`). В приложении не нажимались действия подтверждения импорта.

| Файл | Наблюдение в интерфейсе | Результат |
|---|---|---|
| `corrupt-image.json` | Показано сообщение «изображение повреждено или не читается», предпросмотр не открылся; в навигации осталось 3 проекта | PASS |
| `over-24mp-image.json` | Валидный PNG 5000×5000 (25 000 000 пикселей) декодировался и был отклонён сообщением «разрешение превышает 24 мегапикселя»; предпросмотр не открылся, осталось 3 проекта | PASS |
| `valid-image.json` | Открылся предпросмотр одной входящей записи при трёх текущих; проект не был добавлен. Нажата только «Отмена», после закрытия по-прежнему 3 проекта | PASS |

Покадровые доказательства: `web-corrupt-image-error.png`, `web-over-24mp-error.png`, `web-valid-preview.png`. Повторяемые синтетические fixtures и их генератор находятся рядом. Тест проверяет браузерное декодирование, UI-отказ и UI-предпросмотр. Встроенное API окружения не предоставило `indexedDB` в read-only evaluation scope, поэтому revision IndexedDB отдельно напрямую не считался; подтверждение отмены и отсутствие новой записи проверены по UI, а кодовой контроль показал, что `save()` вызывается только после отдельного подтверждения.

Ограничение: вкладка запускалась на локальном HTTP origin `127.0.0.1`, а не на production HTTPS и не на физическом телефоне.
